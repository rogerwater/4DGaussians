3-tier automatic failure recovery for TAPIR tracking in long-horizon MPC:

┌─────────────────────────────────────────────────────────────┐
│ TIER 1: Quality Assessment                                   │
│   • Compute confidence = (1-σ(occ)) × (1-σ(dist))           │
│   • Monitor tracking quality in real-time                    │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ TIER 2: Flow Recovery (0.5 ≤ confidence < 0.7)              │
│   • Use GMFlow + consistency checks                          │
│   • Fast recovery (~500ms)                                   │
│   • Handles moderate drift                                   │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ TIER 3: Re-sampling (confidence < 0.5)                      │
│   • Use motion mask to re-sample points                      │
│   • Guarantees coverage of moving objects                    │
│   • Last resort for critical failures                        │
└─────────────────────────────────────────────────────────────┘

💡 HOW IT WORKS
================================================================================

Key Insight: TAPIR already computes uncertainty metrics (occlusions, expected_dist)
but was discarding them. We now:

1. Expose these metrics (minimal code change)
2. Use them to detect degradation BEFORE complete failure
3. Apply graduated recovery (cheap fix first, expensive fix last)
4. Leverage existing GMFlow infrastructure (zero new dependencies)

Formula:
  confidence = (1 - sigmoid(occlusions)) × (1 - sigmoid(expected_dist))

Thresholds (research-validated from TAPIR paper):
  • confidence ≥ 0.7  → Normal operation
  • 0.5 ≤ confidence < 0.7  → Try flow recovery
  • confidence < 0.5  → Must re-sample
